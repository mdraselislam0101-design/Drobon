# UserType capability audit — Pump 22

**Revalidated:** 2026-09-29 against the current worktree, shared contracts, routed API, stores, Web pages, tests and current product documents. This replaces the Pump 21 gap claim that structured assessment scope was absent.

`UserType` (`DEVELOPER`, `STUDENT`, `SECURITY_PROFESSIONAL`, `PENTESTER`) is classification/presentation only. It is not authentication, `AccountRole`, project ownership, plan/entitlement, quota, rate-limit, target or DAST permission. The same existing platform and scan/finding/report engines serve every profile. Assessment UI visibility is a UX choice; the owner-scoped assessment API is not UserType-gated.

## Status vocabulary

- **IMPLEMENTED** — exercised platform capability with matching evidence.
- **PARTIAL** — useful scoped behavior exists, while a named limitation remains.
- **NOT_IMPLEMENTED / DEFERRED** — no provider/catalog/course/etc. is shipped or represented as live.
- **LIMITATION** — explicit security/product boundary, not evidence of verification.
- **N/A** — layer does not apply to the capability.

Each row has an overall category/status and separate evidence/status for **UI, API, AUTHZ, persistence, security, tests, controlled API E2E, and docs**. API/route integration is not browser E2E.

## Scope decisions and deferred gaps

- **Shared engine, no UserType bypass:** all four profiles use the existing project/source/scan/finding/remediation/report/assistant systems. UI classification may change navigation only. The assessment routes remain usable by any authenticated owner of that project; the Professional/Pentester panel is a presentation surface, not an API privilege.
- **Developer Git/CI:** no live provider was present to integrate securely. This is explicitly deferred, not presented as working. Uploaded source snapshots and manual scans remain real features.
- **Student learning:** existing explanations, next steps, and history/progress are meaningful Student workflows. Courses, assignments, grades and teacher administration are not claimed or invented.
- **Pentester / third-party target permission:** the software can enforce URL/network safety and project ownership, not establish another party's legal consent. A declaration is user-authored, target-specific and `USER_DECLARED`, never “verified.”
- **Dataset lock:** no real or bundled vulnerability catalog/feed was added. SCA stays `NOT_ASSESSED` / `NO_DATA_LOADED`.
- **Storage posture:** JSON persistence is bounded, restart-safe and architecture-consistent but single-process/single-writer; no PostgreSQL, broad production database, separate scanner engine or speculative integration was introduced.
- **Browser E2E:** the repository has no configured browser automation runner. Do not describe HTTP tests, route tests, component tests or dev-server smoke as browser E2E. The exact final smoke outcome is recorded in `docs/BUILD_VERIFICATION.md`.
