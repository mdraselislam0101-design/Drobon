# Testing guide

Every package ships real tests; nothing passes because of a placeholder.
Framework: Vitest 4 everywhere (`vitest run` per workspace), React Testing
Library + jsdom for the Web.

### Pump 11 — passive DAST coverage

- Shared contracts: strict DAST result/observation/finding shapes, bounded counts and byte values, URL syntax, same-host endpoint invariants, partial-result honesty and cross-record consistency.
- API target policy: URL parsing/canonicalization, local/reserved address rejection, IPv4/IPv6 ranges, literal-IP override resistance, mixed DNS answers, resolver timeout/rebinding, and independent redirect checks.
- Passive rules/engine: observed security headers, cookie value redaction, CORS behavior, content-type-limited mixed content, deterministic findings, redirect limits/loops/cross-host/private/downgrade rejection, body/time/request caps, aborts and no crawling/execution.
- HTTP transport: a **controlled loopback-only fixture** checks the real Node request path, pinned lookup, GET-only unauthenticated headers, response-byte cap, timeout and abort. Production loopback rejection remains enabled.
- API lifecycle: owner-only project target configuration, malformed/unsafe target rejection, no quota consumption on rejected targets, idempotency, client claim rejection, synthetic transport response, and durable project target/result/finding restart.
- Web/client: target set/remove flow, DAST unavailable until the server confirms a target, observed evidence display, scope limitations, and encoded route/body boundary tests.
- No test contacts an arbitrary/public host. The API scan/restart fixture uses a synthetic resolver plus synthetic transport response and is **not** represented as a real network DAST exchange.

## Running

```bash
npm run test                                   # everything, in order
npm run test --workspace @drobon/api           # one package (rebuild shared first if contracts changed)
npx vitest run --workspace @drobon/web         # from repo root, web only
```

Watch mode during development: `npx vitest --workspace @drobon/api`
(or `cd apps/api && npx vitest`). Typecheck and lint are separate gates:
`npm run typecheck`, `npm run lint`.

## Notes

- API tests boot real servers on ephemeral loopback ports and speak real
  HTTP via `fetch` — no supertest, no mocks of the app itself.
- The Web `previewHeaders` test runs a real `vite build` + `vite preview`
  and asserts production headers, SPA fallback and bundle hygiene. It is the
  slowest test (~tens of seconds) and doubles as the production-build proof.
- Worker tests use millisecond budgets and injected sleeps — no fake timers,
  no flakes by design (timeouts in tests are generous relative to budgets).
- Static tests (`staticSafety`, `staticWeb`) scan `src/` for forbidden
  patterns (exec primitives, env reads outside the boundary, dangerous DOM
  APIs). Keep them green by construction, not by carve-out.
- Coverage thresholds are NOT configured in Pump 1 (deliberate — the suite
  asserts behaviors and contracts, not line percentages). Revisit in a later
  Pump if coverage gating is wanted.

### Pump 12 — production findings and reports

- Shared contracts: bounded page/detail guards bind project, scan, finding, scanner and filter state; report guards verify schema, closed shapes, summaries, inventory and honest vulnerability-intelligence state.
- Finding identity: `apps/api/test/findingIdentity.test.ts` pins normalized deterministic SHA-256 fingerprints, scanner/project/rule/location/context separation and no evidence disclosure in the fingerprint.
- Report builder/store: `apps/api/test/reports.test.ts` covers canonical serialization, real content/integrity digests, inert Markdown, idempotent per-scan persistence, restart retrieval, cross-project lookup rejection and fail-fast tamper detection.
- Local API E2E: `apps/api/test/reportsApi.test.ts` uses real HTTP routes, registration/login, projects, source upload, all four scan engines and bounded DAST fixtures; verifies server-side filters/pagination, safe finding details, JSON/Markdown exports, injection and secret redaction, IDOR/cross-account/cross-project denial, archived-history behavior, FREE quota and PRO exemption, report quota non-consumption, durable API restart, and `NO_DATA_LOADED` / `NOT_ASSESSED` honesty. The DAST target/transport are deterministic controlled fixtures; this is not a public-target scan.
- Web boundary/UI: `apps/web/test/client.test.ts` checks authenticated, content-type/filename/stream-size bounded downloads; `apps/web/test/findingsReportsUi.test.tsx` checks project summary, server-side filters, safe detail rendering, report generation/retrieval, coverage, SBOM state and not-assessed messaging. SAST/Secrets UI suites exercise the same new server-page API and safe detail component.
- Full cumulative verification still runs all Pumps 1–11 workspace tests; no external vulnerability catalog or public target is used.

### Pump 13 — production remediation and finding lifecycle

It does not contact a public target or run active DAST.

- Cumulative compatibility is checked by the full `npm run verify` pipeline; Pump 1–12 suites remain required and are not replaced by these focused tests.
