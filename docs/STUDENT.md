# Student workflow (Pump 18)

Pump 18 adds a Student-facing entry route, progress/history presentation, and clearer guidance labels over the existing shared security core. Student is not a separate scanner, project, quota, finding, report, or assistant system. The matrix below records each scoped capability and its implementation or explicit limitation.

## Student workflow surface

The dashboard is a bounded progress/history surface based on persisted server state. Project-level source, scan, finding, lifecycle, report and assistant features remain shared with Developers. The Student classification changes workspace presentation only; authentication, role authorization, project ownership, plan entitlement, account/device quota, rate limits and scan lifecycle remain authoritative on the server.

- FREE remains three scans per UTC month per account, with the existing shared-device anti-abuse controls. PRO is available only through the existing server entitlement (`PRO + ACTIVE`).
- Account enabled/disabled state is not modeled. DAST consumes normal scan quota and is not an active crawler. External credential verification is not performed.
- Assistant provider state remains `NONE`; deterministic supported answers use authorized saved evidence, and unsupported generation remains unavailable. Pump 19 adds aggregate assessment/verification/DAST question handlers to that shared assistant.
- Shared dashboard scan cards also show a completed DAST observation count and completed SCA assessment/dataset states when those persisted results are available; neither is a security verdict or complete-coverage claim.
- External AEGIS intelligence remains separate. No vulnerability data is loaded or bundled; SCA without it remains `NOT_ASSESSED` / `NO_DATA_LOADED`.

## Verification map

Pump 18 repository verification totals, test results, and the controlled local Student API journey are recorded in `docs/BUILD_VERIFICATION.md`; test organization is recorded in `docs/TESTING.md`. The API journey is real HTTP integration against temporary local stores, not browser E2E or a public-target assessment. No “100% security” or full-browser-E2E claim is made.
